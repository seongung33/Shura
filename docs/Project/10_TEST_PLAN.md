# Shura 테스트 계획

> 마지막 증거 점검: **2026-07-31**
> 이번 문서 갱신에서는 Unity를 새로 조작하지 않았다. 결과는 Git의 기존 AI 활용 기록과 최신 로컬 `Editor.log`에 남은 Play 실행 흔적을 구분해 적었다.

## 1. 테스트 원칙

- “내 PC에서 한 번 실행됨”을 완료로 보지 않는다.
- 기능 테스트, 두 PC 테스트, 새 Clone 테스트, Web 링크 테스트를 분리한다.
- 버그는 재현 순서와 기대·실제 결과를 함께 기록한다.
- 8월 7일부터는 새 기능보다 회귀 테스트를 우선한다.

### 결과 표기

- **통과:** 현재 기준 브랜치·커밋에서 절차와 기대 결과를 직접 확인
- **로그 확인:** 최신 Unity 로그에 기대 동작 흔적이 있으나 이번 점검에서 절차 전체를 재실행하지 않음
- **과거 통과:** 과거 기능 브랜치의 Play 검증 기록은 있으나 현재 통합 브랜치 회귀가 필요
- **부분:** 일부 결과만 확인했거나 임시 프리팹·테스트 값 사용
- **실패:** 재현 결과가 기대와 다름
- **미실행:** 검증 증거 없음
- **차단:** 선행 구현 또는 통합이 없어 실행할 수 없음

### 현재 증거 요약

- 이동, 카메라, 체력·사망, 경험치·레벨 증가는 과거 AI 활용 문서에 수동 Play 검증이 기록되어 있다.
- 최신 로컬 Unity 로그에는 경험치 레벨 2·3 상승, 체력 감소·회복, 60초 라운드 종료, 임시 보스 등장, 승리·패배 실행 흔적이 있다.
- 로컬 아이템 스크립트 반영 이후 어셈블리 재로드 기록이 있으며, 마지막으로 발견된 과거 C# 오류 이후 컴파일 단계가 다시 완료되었다.
- 자동화된 EditMode·PlayMode 테스트는 없다.
- Build Settings에는 `NetworkTest`만 활성화되어 있어 `StageTest`와 최종 게임 빌드 회귀는 별도로 필요하다.

## 3. 현재 전투 구조 회귀 테스트

새 스킬·공격·피해 대상 또는 프리팹 계층을 수정했을 때 실행한다.

| ID | 항목 | 절차 | 기대 결과 | 결과 |
|---|---|---|---|---|
| C-001 | 스킬 실행 성공 | 유효한 `SkillData`, 대상, `Projectile` 프리팹으로 `SkillRunner.TryRun` 실행 | `true` 반환, 발사 위치에 생성, 데이터의 속도·피해 적용 | ☐ |
| C-002 | 스킬 실행 실패 | 데이터·대상·프리팹 중 하나를 비우거나 `Projectile` 없는 프리팹 사용 | `false` 반환, 잘못 생성된 오브젝트가 남지 않고 쿨다운 미소비 | ☐ |
| C-003 | 가장 가까운 적 탐색 | 범위 안 서로 다른 거리에 적 배치 | `Enemy` 레이어이면서 `EnemyHealth`가 있는 가장 가까운 적 선택 | ☐ |
| C-004 | 자식 Collider 피해 | 적 루트에 `EnemyHealth`, 자식에 Collider 배치 후 투사체 명중 | 부모의 `IDamageable`을 찾아 정확히 1회 피해 | ☐ |
| C-005 | 잘못된 레이어 무시 | `EnemyHealth`가 있지만 `enemyLayer` 밖인 대상과 충돌 | 피해와 투사체 소멸이 발생하지 않음 | ☐ |
| C-006 | 플레이어 접촉 피해 | `Player` 태그·Collider·`PlayerHealth`가 있는 플레이어와 적이 접촉 | 공격 간격마다 `IDamageable`을 통해 체력 감소 | ☐ |
| C-007 | 경험치 드롭·습득 | 적 처치 후 생성된 구체와 플레이어 Trigger 충돌 | 설정한 보상량 획득, 구체 제거, 필요 시 여러 레벨 연속 상승 | ☐ |
| C-008 | 대상 사라짐 재탐색 | 투사체 비행 중 기존 대상 제거, 범위 안 다른 적 유지 | 다른 적 재탐색, 없으면 투사체 제거 | ☐ |

### 현재 전투 증거 판단

- `C-006`은 최신 로그에서 플레이어 체력이 10씩 감소하고 0에서 패배한 흔적이 있으나, 공격 간격까지 이번 점검에서 측정하지 않아 **로그 확인**이다.
- `C-007`은 과거 Play 기록과 최신 레벨 상승 로그가 있으나 `ExperienceOrb` 폴더 이동 후 전체 드롭·습득을 다시 실행해야 한다.
- 그 외 항목은 현재 브랜치에서 절차 전체를 다시 실행하지 않았으므로 체크하지 않는다.

## 7. 새 Clone 검증

팀원의 기존 프로젝트가 아닌 새 폴더에서 확인한다.

1. 저장소를 Clone한다.
2. `develop` 또는 제출 시 `main`을 Checkout한다.
3. README에 적힌 정확한 Unity 버전으로 연다.
4. Unity가 `Library`를 새로 생성하도록 기다린다.
5. Console 오류를 확인한다.
6. Main 씬을 실행한다.
7. Windows 또는 Web 빌드를 생성한다.

### 현재 새 Clone 전 정리할 항목

- `feat/map_generate`, `origin/develop`, HUD 수정 브랜치와 로컬 아이템 작업을 하나의 검증 브랜치로 통합한다.
- `PlayerTest`의 `PlayerExperience` 중복 가능성을 제거하고 경험치가 한 번만 적용되는지 확인한다.
- `CombatTest`가 카메라만 있는 현재 상태라면 테스트 목적을 복구하거나 문서에서 제외한다.
- `StageTest`의 2·3웨이브 시작 시간을 서로 다르게 저장한다.
- `MagnerPickup.cs` 파일명을 클래스명 `MagnetPickup`과 맞추고 Unity에서 `.meta` 보존을 확인한다.
- Build Settings에 실제 통합 게임 씬을 등록한다.

## 9. 제출 차단 버그

다음 문제는 다른 작업보다 먼저 해결한다.

- 게임을 시작할 수 없음
- Web 링크가 열리지 않음
- 두 플레이어가 방에 들어갈 수 없음
- 한 판을 끝낼 수 없음
- 연계 효과가 발동하지 않음
- 진행 중 반복적으로 멈춤
- 조작 방법을 알 수 없음
- Console 오류가 지속적으로 쌓임
