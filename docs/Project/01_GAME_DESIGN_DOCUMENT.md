# Shura 게임 기획서

> 최종 정리: **2026-08-03 KST**
> 이 문서는 게임 경험과 규칙의 정본이다. 속성·영웅 상세는 `11_CONCEPT_AND_HERO_DESIGN.md`, 현재 구현은 `12_CURRENT_PROJECT_STATUS.md`를 따른다.

## 1. 한 줄 소개

**두 플레이어가 서로 다른 스킬을 같은 적에게 연계해 대규모 반응을 일으키며 살아남는 2D 협동 생존 액션 게임.**

프로젝트명 `Shura`는 현재 코드명이다. 최종 제목과 세계관은 핵심 플레이가 검증된 뒤 확정한다.

## 2. 기획 의도

일반적인 뱀서류 게임은 플레이어 개인의 빌드 완성과 화력 증가가 중심이다. Shura는 여기에 다음 질문을 더한다.

> “내가 강해지는 것뿐 아니라, 동료의 스킬을 보고 다음 행동을 선택하게 만들 수 있을까?”

플레이어는 각자 자동 공격과 스킬을 보유한다. 서로 다른 플레이어가 일정 시간 안에 같은 적 또는 같은 영역에 호환되는 효과를 적용하면 강력한 **연계 반응**이 발생한다. 따라서 동료의 위치, 보유 스킬, 공격 타이밍을 확인하는 행동이 핵심 재미가 된다.

## 3. 목표 플레이 경험

- 혼자 적을 제거하는 것보다 함께 스킬을 연결했을 때 확실히 강해진다.
- 화면을 가득 채운 적을 연계 효과로 한 번에 정리하는 쾌감이 있다.
- 조작은 단순하지만 위치 선정과 동료와의 거리에는 판단이 필요하다.
- 한 판이 짧아 실패 후 즉시 다시 시도할 수 있다.
- 캐릭터와 스킬 조합을 바꾸면서 다른 협동 방식을 발견한다.

## 4. 핵심 게임 루프

1. 캐릭터를 선택하고 2인 협동 세션을 시작한다.
2. 이동하며 자동 공격으로 몰려오는 적을 처치한다.
3. 경험치를 획득하고 레벨업 시 스킬 또는 강화를 선택한다.
4. 동료가 적용한 속성에 맞춰 자신의 스킬을 사용한다.
5. 연계 반응으로 적 무리를 제거하고 다음 웨이브를 버틴다.
6. 15분까지 생존한 뒤 등장하는 보스를 처치하면 승리한다.
7. 결과 화면에서 생존 시간, 처치 수, 연계 발동 수를 확인한다.

## 5. 기본 규칙

| 항목 | 해커톤 MVP 기준 |
|---|---|
| 시점 | 2D 탑다운 |
| 한 판 길이 | 15분 목표 |
| 기본 인원 | 2명 |
| 장기 인원 | 최대 4명 |
| 공격 | 기본 공격 자동 발동 |
| 이동 | WASD 또는 방향키 |
| 성장 | 경험치 획득 후 레벨업 선택 |
| 승리 | 제한 시간 생존 후 보스 처치 |
| 패배 | 캐릭터 한 명이 사망 |
| 주요 지표 | 생존 시간, 처치 수, 연계 발동 수 |

## 6. 스킬 연계 시스템

스킬은 독·물·번개·얼음·흙·바람·불 중 하나의 속성을 가질 수 있다. 적은 최근에 받은 속성, 적용한 플레이어와 시간을 기억한다. 서로 다른 플레이어가 제한 시간 안에 호환 속성을 적용하면 연계 반응이 발생한다.

정확한 7속성 규칙과 계획 조합 4개는 `11_CONCEPT_AND_HERO_DESIGN.md`에서만 관리한다. 제출 완료 기준은 그중 최소 2개가 실제 2인 네트워크 전투에서 작동하는 것이다.

### 연계 판정 원칙

- 서로 다른 플레이어의 공격이어야 한다.
- 같은 적 또는 같은 영역에 정해진 시간 안에 적용해야 한다.
- 동속성과 정의되지 않은 조합은 불이익 없이 무반응으로 처리한다.
- 반응이 발생하면 화면, 소리, 텍스트로 명확하게 알려준다.
- 반응 피해는 일반 공격보다 눈에 띄게 강해야 한다.
- 연속 발동에 따른 무한 루프를 막기 위해 짧은 내부 쿨다운을 둔다.

## 7. 캐릭터 방향

영웅은 고유 무기, 기본공격과 전용 스킬 세트를 가진다. 영웅 1호는 주몽이며 영웅 2호는 미정이다. 영웅별 상세 스킬을 이 문서에 복제하지 않고 `11_CONCEPT_AND_HERO_DESIGN.md`에서 관리한다.

장기적으로 공격형·제어형·지원형·생존형 성향을 확장하되 강제적인 탱커·딜러·힐러 조합은 피한다.

## 8. 적과 웨이브

### MVP 적 구성

| 적 | 행동 | 개발 목적 |
|---|---|---|
| 추적형 | 가장 가까운 플레이어를 따라간다 | 기본 전투 검증 |
| 돌진형 | 일정 거리에서 예고 후 돌진한다 | 회피와 위치 선정 |
| 원거리형 | 멀리서 투사체를 발사한다 | 화면 이동 유도 |
| 보스 | 위 패턴 중 2개를 조합한다 | 한 판의 종료 목표 |

### 웨이브 원칙

- 시간에 따라 생성 수와 체력이 증가한다.
- 새로운 적은 한 번에 하나씩 소개한다.
- 보스 직전에는 짧은 정리 시간을 준다.
- 멀티플레이 인원에 따라 적 체력 또는 생성 수를 조정한다.

### 0~15분 라운드 기준

아래 구간은 첫 구현 기준이며 플레이 테스트 후 수치와 적 종류를 조정한다.

| 시간 | 진행 |
|---|---|
| 0~3분 | 기본 추적형 적을 적은 수로 생성해 이동·공격·아이템 습득을 익히게 한다 |
| 3~6분 | 생성 수와 체력을 올리고 두 번째 적 유형을 섞는다 |
| 6~9분 | 원거리 또는 돌진형 적을 본격적으로 추가한다 |
| 9~12분 | 적 조합과 생성 빈도를 높이고 강화 개체를 섞는다 |
| 12~15분 | 가장 높은 일반 웨이브와 보스 직전 정리 구간을 진행한다 |
| 15분 | 최종 보스를 등장시키며, 보스 처치 시 클리어한다 |

MVP에서는 캐릭터 한 명이 사망하면 즉시 패배 처리하고 전투를 정지한다. 부활이나 관전은 이후 범위다.

## 9. 화면 구성

- 중앙: 실제 전투 화면
- 좌측 상단: 플레이어 체력과 캐릭터 정보
- 우측 상단: 남은 시간과 처치 수
- 하단: 보유 스킬과 쿨다운
- 연계 발동 시: 연계 이름과 짧은 강조 효과
- 결과 화면: 승패, 생존 시간, 처치 수, 연계 발동 수

## 10. 아트와 사운드 방향

- 해커톤 기간에는 **2D 픽셀 또는 단순한 2D 도형 기반**으로 통일한다.
- 3D 전환은 해커톤 전에는 검토하지 않는다.
- 캐릭터와 적은 실루엣과 색만으로 구분 가능해야 한다.
- 투사체, 피격, 연계 반응은 캐릭터보다 더 밝고 선명하게 표현한다.
- 외부 에셋을 사용하면 출처와 라이선스를 즉시 기록한다.
- 사운드는 공격, 피격, 연계, 레벨업, 승리·패배를 우선한다.

## 11. 서사 전달 방향

Shura는 스토리 진행이 플레이를 끊는 게임이 아니다. 컷신, 긴 대화, 퀘스트형 상호작용을 중심에 두지 않고, **맵의 해금 순서와 환경 변화로 세계관을 간접적으로 보여주는 환경 서사 방식**을 사용한다.


### 11.1 맵 해금과 이야기 진행

- 맵은 단순한 난이도 순서가 아니라 세계관의 사건 순서에 맞춰 해금한다.
- 새로운 맵이 열릴 때마다 공간의 분위기, 건축물, 색과 조명, 배경음, 적과 보스의 모습이 달라지며 이전 맵 이후에 벌어진 변화를 보여준다.
- 플레이어가 별도의 설명을 읽지 않아도 맵을 차례대로 플레이하면 세계가 어떻게 변했는지 대략 추측할 수 있어야 한다.
- 각 맵의 구체적인 시대, 사건, 분위기 변화는 세계관 연표가 확정된 뒤 연결한다.

### 11.2 맵에 배치할 서사 단서

서사 단서는 전투를 멈추고 조사하는 상호작용 오브젝트가 아니라, 이동과 전투 중 자연스럽게 보이는 요소로 배치한다.

- 파괴되거나 변형된 건축물과 생활 흔적
- 반복해서 등장하는 문양, 표식, 장비, 조형물
- 이전 사건의 결과를 보여주는 잔해와 지형 변화
- 해당 맵의 시대와 세력을 드러내는 배경 오브젝트
- 적과 보스의 외형 변화 및 맵과 연결되는 디자인
- 조명, 날씨, 배경음과 효과음의 변화
- 맵 입장 화면에 표시하는 짧은 장소 설명 또는 문장

중요한 단서는 한 번 놓치면 알 수 없는 수집품으로 만들지 않는다. 같은 의미를 가진 시각 요소를 여러 위치에서 반복해, 전투에 집중해도 분위기와 사건의 흔적을 인식할 수 있게 한다.

### 11.3 캐릭터 서사

- 캐릭터 선택 또는 해금 화면에서 각 캐릭터의 출신, 과거 사건, 현재 목표, 고유 무기의 의미를 짧게 제공한다.
- 캐릭터의 무기, 특수공격, 액티브 스킬은 가능하면 개인 서사와 연결한다.
- 캐릭터와 관련된 흔적을 특정 맵의 배경 요소에 배치해 개인 서사와 전체 세계관을 연결할 수 있다.
- 플레이 중 긴 설명을 강요하지 않고, 더 알고 싶은 플레이어가 캐릭터 소개에서 확인하는 구조로 만든다.

### 11.4 구현 우선순위

- 해커톤 MVP에서는 컷신이나 복잡한 스토리 시스템을 만들지 않는다.
- P0 기능 완료 후 첫 맵에 비상호작용형 서사 단서 2~3개와 짧은 캐릭터 소개를 추가한다.
- 여러 맵의 해금 순서와 본격적인 환경 변화는 해커톤 이후 세계관 연표와 함께 확장한다.

## 12. 아직 결정하지 않은 항목

- 최종 게임 제목
- 세계관의 구체적인 사건·연표와 캐릭터별 세부 설정
- 맵별 시대, 해금 순서, 분위기 변화
- 최종 픽셀 해상도와 팔레트
- AI 동료를 실제 플레이 기능으로 넣을지 여부
- Steam 출시 시 과금 방식

결정되지 않은 항목은 핵심 플레이 구현을 막지 않는 한 뒤로 미룬다.
