## 4. 현재 반드시 유지할 코드 계약

### 데미지

- 데미지를 받는 대상은 `IDamageable`을 구현한다.
- 공격 코드는 `EnemyHealth`나 `PlayerHealth`의 체력 필드를 직접 변경하지 않고 `IDamageable.TakeDamage(float)`를 호출한다.
- 체력 감소, 사망, 드롭과 사망 이벤트는 피해를 받는 컴포넌트가 처리한다.

### 현재 투사체형 스킬

```text
발동 조건
→ EnemyTargetFinder
→ SkillRunner.TryRun(SkillData, target)
→ Projectile.Initialize
→ IDamageable.TakeDamage
```

- 단순한 유도 투사체 변형은 이 흐름을 재사용한다.
- 범위·근접·지속·버프형 스킬은 현재 `Projectile` 전제를 억지로 복사하지 않고 공통 실행 규격을 먼저 합의한다.

### 프리팹·씬

- 적 루트는 `Enemy` 레이어와 `EnemyHealth`를 유지한다.
- 플레이어의 접촉 Collider와 `PlayerHealth` 배치는 현재 `EnemyAttack`의 탐색 방식과 함께 검증한다.
- 공용 씬·프리팹·ScriptableObject를 변경할 때는 기능 브랜치 간 차이를 먼저 확인한다.

## 5. 확인된 통합 위험

1. 현재 맵 브랜치에 원격 develop의 HUD와 최신 기획 문서가 아직 합쳐지지 않았다.
2. 원격 develop의 HUD 원본은 `Shura.Player.PlayerHealth` 네임스페이스 참조 문제가 있었고 별도 수정 브랜치가 존재한다.
3. `StageTest` 직렬화 값은 `wave2StartTime = 20`, `wave3StartTime = 20`이다. `WaveManager`가 3웨이브를 먼저 판정하므로 2웨이브가 건너뛰어질 수 있다.
4. 보스는 일반 적 프리팹을 임시로 재사용하므로 전용 보스 구현 완료로 볼 수 없다.
5. 회복·자석·경험치 오브 이동은 아직 커밋되지 않았다. 폴더 이동 후 `.meta`와 모든 프리팹 참조를 Unity에서 다시 확인해야 한다.
6. Build Settings에는 `NetworkTest`만 활성화되어 있어 `StageTest`나 최종 게임이 빌드 진입점이 아니다.
7. 스킬 연계, 레벨업 선택, 실제 2인 전투 동기화와 Web 빌드는 아직 핵심 공백이다.

## 6. 다음 통합 순서

1. 현재 로컬 아이템 작업을 Play Mode에서 검증하고 작은 커밋으로 정리한다.
2. `origin/develop`의 HUD·문서와 HUD 수정 브랜치를 현재 작업에 충돌 없이 통합한다.
3. `StageTest`의 웨이브 시작값, 일반 적 보스 대체, 결과 패널 연결을 검증한다.
4. Build Settings에 통합 게임 진입 씬을 등록하고 Windows 세로 슬라이스 빌드를 만든다.
5. 스킬 4개와 연계 반응 2개를 최소 형태로 구현한다.
6. 네트워크 플레이어에 이동·체력·스킬·게임 상태를 연결한다.
7. Web 빌드와 제출용 회귀 테스트를 진행한다.

## 7. AI 활용 요약

현재까지 C# 구현은 생성형 AI 코딩 도구가 제시한 초안을 기반으로 진행되었다. 팀원은 기능 목표와 완료 조건을 정하고, 기존 구조와 충돌하지 않도록 요청 범위를 설계했으며, Unity 씬·프리팹·Inspector 연결, 데이터 입력, Play 검증, 오류 수정 방향 결정, Git·PR과 최종 채택을 담당했다.

도구별 실제 기록, 사람이 수행한 검토와 아직 보완해야 할 프롬프트 내역은 `06_AI_USAGE_TECHNICAL_DOCUMENT.md`에 정리한다.
