## 3. 현재 실행 경로

```text
NetworkTest
→ UGS 초기화·익명 로그인
→ 호스트가 Relay 방 생성, 게스트가 코드 참가
→ 2명 접속 시 호스트 게임 시작
→ NGO가 Main을 모든 참가자에게 로드
→ NetworkStageBootstrap이 EnemySpawner·WaveManager·GameManager 구성
→ 서버가 적·보스·체력·경험치·승패 확정
→ 소유 플레이어가 자신의 입력·HUD·결과 UI 처리
→ 호스트가 재시작 또는 양쪽 로비 복귀
```

`ProjectSettings/EditorBuildSettings.asset`에는 `NetworkTest`와 `Main`이 활성화되어 있다. `StageTest`는 빌드 진입점이 아니라 로컬 기능 검증용이다.

## 4. StageTest와 Main의 관계

- `StageTest`: 정적 로컬 `Player`와 씬에 배치한 `EnemySpawner`·`WaveManager`·`GameManager`를 사용한다. 네트워크 없이 기능 담당자가 빠르게 테스트한다.
- `Main`: 로비에서 넘어온 `NetworkPlayer`를 사용하고 `NetworkStageBootstrap`이 같은 스테이지 컴포넌트를 런타임에 조립한다.
- 두 씬은 `LoadSceneMode.Single` 흐름에서 동시에 실행되지 않는다.
- 게임 로직 재사용은 의도된 구조지만 라운드 시간·웨이브·적·보스 참조가 두 씬에 따로 있어 값이 어긋날 수 있다.

현재 실제 차이는 다음과 같다.

| 설정 | StageTest 로컬 작업 | Main 통합본 |
|---|---|---|
| 라운드 | 10초 | 60초 |
| 웨이브 전환 | 3초 / 4초 | 20초 / 40초 |
| 보스 | `BossJangsanTiger.prefab` | 일반 `Enemy.prefab` 임시 사용 |

최종 15분 데이터는 공용 `StageConfig` 또는 동등한 ScriptableObject로 옮겨 두 씬이 같은 값을 읽도록 하는 것이 안전하다.

## 5. 네트워크 권한 경계

| 데이터·행동 | 권한 |
|---|---|
| 플레이어 입력·이동 Transform | 소유 클라이언트 |
| 로컬 기본공격·스킬 오브젝트 생성 | 소유 클라이언트 |
| 적 생성·AI·공격·Transform | 서버 |
| 적 체력·사망·제거 | 서버. 클라이언트 명중은 RPC 요청 |
| 경험치 오브 생성·획득·제거 | 서버. 요청자의 소유권과 거리 검증 |
| 플레이어 체력·사망·EXP·레벨 | 서버 `NetworkVariable` |
| 승리·패배 | 서버 |
| HUD·결과 표시 | 각 소유 플레이어 로컬 UI |

현재 투사체·장판은 `NetworkObject`가 아니며 상대 화면에 동일하게 복제되지 않는다. `EnemyHealth.RequestDamageRpc`도 피해량·명중 위치·쿨다운을 서버에서 엄격히 재검증하지 않는다. 제출용 협동 프로토타입 경계이며 서비스 수준의 권위적 전투 판정은 아니다.

## 6. 검증 증거

2026년 8월 2일 `83b8783` 기록에서 같은 Windows 빌드의 Editor·실행 파일로 다음을 확인했다.

- 2인 Relay 참가
- `Main` 동시 전환
- 플레이어·적·HUD·웨이브 표시
- 플레이어 사망과 양쪽 패배 결과
- 양쪽 로비 복귀

확인하지 않았거나 별도 증거가 필요한 항목:

- 장산범 보스 Play 동작과 2인 승리
- 결과 후 연속 재시작
- 로비 복귀 후 새 방 생성·참가
- 강제 종료·호스트 이탈
- 10분 이상 지속 플레이
- 상대방 스킬 시각 효과와 속성 상태 일치
- 연계 반응
- Web 빌드

세부 테스트 ID와 결과는 `10_TEST_PLAN.md`에서 관리한다.

## 7. 통합 위험

1. 장산범과 주몽 SkillData 폴더 이동이 미커밋 상태라 브랜치 전환·정리 전에 반드시 보존해야 한다.
2. `StageTest`와 `Main`의 웨이브·보스 설정이 분리돼 있어 한쪽 수정이 다른 쪽에 자동 반영되지 않는다.
3. 네트워크 스크립트는 `Lobby`, `Player`, `Enemy`, `Stage`, `Result` 책임별 폴더로 정리되었으며, 기존 씬·프리팹 참조를 유지하도록 각 `.meta` GUID를 보존했다.
4. 네트워크 투사체·속성·연계가 없어서 피해 결과 외의 협동 전투 상태가 완전히 공유되지 않는다.
5. 자동화된 EditMode·PlayMode 테스트가 없고 현재 통합 Windows 실행 파일이 저장소의 `Builds`에 남아 있지 않다.
6. 문서 정리 전 다수 문서가 7월 31일 브랜치 상태를 반복 기록해 실제 코드와 충돌했다. 이후 현재 상태는 이 문서 한 곳에서만 갱신한다.

## 8. 다음 작업 순서

1. 장산범·SkillData 이동 작업을 Unity에서 검증하고 작은 커밋으로 보존한다.
2. 장산범을 `Main`에도 연결하고 로컬 승리 후 2인 승리·재시작을 검증한다.
3. 최소 연계 2개를 위한 속성 기록·서버 판정·피드백을 구현한다.
4. 네트워크 플레이어에 편전·적토마와 스킬 상태를 연결한다.
5. 레벨업 능력치/스킬 선택을 구현한다.
6. 공용 스테이지 데이터로 15분 웨이브와 보스 설정을 통합한다.
7. 강제 이탈·장시간·새 방·새 Clone 회귀를 수행한다.
8. Web 빌드·호스팅·브라우저 Relay를 검증하고 제출 후보를 고정한다.
