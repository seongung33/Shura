# Shura MVP 범위 및 장기 로드맵

## 1. 범위 설정 목적

현재 팀은 Unity 게임 개발 경험이 없고, 2026년 8월 10일까지 플레이 가능한 빌드와 문서를 제출해야 한다. 따라서 해커톤에서는 “완성된 작은 한 판”을 우선하며, 장기 목표인 4인 온라인 협동과 Steam 출시는 별도 단계로 분리한다.

## 2. 성공 기준

해커톤 MVP는 다음 질문에 모두 `예`라고 답할 수 있으면 성공이다.

1. 링크를 받은 사람이 별도 유료 프로그램 없이 게임을 실행할 수 있는가?
2. 30초 안에 이동과 공격 방법을 이해할 수 있는가?
3. 2명이 함께 플레이하거나, 최소한 협동 구조를 직접 확인할 수 있는가?
4. 두 플레이어의 스킬이 연계되어 일반 공격과 다른 결과를 만드는가?
5. 시작부터 승리 또는 패배까지 한 판이 끝나는가?
6. 오류 없이 30~60초 플레이 영상을 녹화할 수 있는가?

## 3. 우선순위

### P0: 제출을 위해 반드시 필요한 기능

- 플레이어 이동과 카메라
- 기본 공격 자동 발동
- 체력, 피해, 사망
- 적 추적과 생성
- 경험치와 레벨업 선택
- 기본 스킬 4개
- 플레이어 간 연계 반응 2개
- 시간 기반 웨이브
- 보스 또는 명확한 종료 웨이브
- 승리·패배·재시작
- 2인 플레이
  - 목표: 온라인 2인
  - 폴백: 같은 PC의 로컬 2인
- Windows 개발 빌드
- 심사용 Web 빌드
- 최소 UI와 사운드

### P1: P0 완료 후 추가

- 캐릭터 선택 2종
- 다운 상태와 동료 부활
- 엘리트 적
- 추가 연계 반응 1개
- 간단한 옵션과 음량 조절
- 연계 발동 통계
- 튜토리얼 안내 화면

### P2: 해커톤 이후

- 최대 4인 온라인
- 매치메이킹과 로비 고도화
- 다양한 캐릭터와 스킬 트리
- 메타 성장과 저장
- 여러 맵과 보스
- Steam 업적·초대·친구 참가
- 패드 지원
- 접근성 설정
- AI 동료 또는 AI 디렉터

## 4. 명시적으로 하지 않을 것

8월 10일 이전에는 다음 항목을 시작하지 않는다.

- 3D 그래픽 전환
- 계정과 자체 서버
- 상점과 과금
- 복잡한 인벤토리
- 스토리 컷신
- 절차적 맵 생성
- 4인 네트워크 최적화
- 랭킹과 경쟁 모드
- 모바일 조작 대응

## 5. 네트워크 결정 게이트

멀티플레이는 차별점이지만 전체 일정을 무너뜨릴 수 있는 가장 큰 위험이기도 하다.

### 7월 27일까지 확인할 것

- 두 대의 PC가 방 생성과 참가에 성공한다.
- 두 플레이어의 위치가 서로 보인다.
- 적 하나의 위치와 체력이 동일하게 보인다.
- Windows 빌드에서 접속된다.
- Web 빌드 또는 제출 가능한 폴백 경로가 확인된다.

### 판단

- 성공: 온라인 2인을 P0로 유지한다.
- 불안정: 온라인 작업 범위를 이동·체력·핵심 스킬 동기화로 제한한다.
- 실패: 해커톤 빌드는 로컬 2인으로 제출하고, 온라인 구조와 시도 내역을 기술 문서에 기록한다.

온라인 구현 실패를 늦게 인정하는 것보다 7월 27일에 폴백을 선택하는 것이 낫다.

## 6. 해커톤 이후 로드맵

### 단계 1: 사전 과제 제출판

- 2인 협동
- 1개 맵
- 8분 한 판
- 2개 연계 반응
- Web 및 Windows 빌드

### 단계 2: 코어 프로토타입

- 4인 네트워크 구조
- 4개 캐릭터
- 10개 이상 스킬
- 6개 이상 연계 반응
- 로비, 재접속, 패드

### 단계 3: Steam 데모

- 20~30분 콘텐츠
- 2개 맵
- 2개 보스
- 설정·저장·Steam 초대
- 튜토리얼과 사용자 테스트

### 단계 4: 얼리 액세스 후보

- 반복 플레이 구조
- 메타 성장
- 콘텐츠 제작 파이프라인
- 밸런스 텔레메트리
- 커뮤니티 피드백과 업데이트 계획
