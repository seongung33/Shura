# Shura MVP 범위 및 장기 로드맵

> 범위 정본. 현재 구현 상태는 `12_CURRENT_PROJECT_STATUS.md`, 테스트 결과는 `10_TEST_PLAN.md`를 따른다.

## 1. 범위 설정 목적

2026년 8월 10일까지 플레이 가능한 빌드와 제출 문서를 완성해야 한다. 제출판은 기능 수보다 **시작부터 승패까지 이어지는 작은 한 판**과 Shura의 차별점인 **2인 속성 연계**를 우선한다.

## 2. 성공 기준

다음 질문에 모두 `예`라고 답할 수 있으면 제출 MVP에 성공한 것으로 본다.

1. 링크를 받은 사람이 별도 유료 프로그램 없이 실행할 수 있는가?
2. 30초 안에 이동과 자동 공격 방식을 이해할 수 있는가?
3. 두 사람이 같은 전투에 참가해 핵심 상태를 공유하는가?
4. 서로 다른 플레이어의 속성이 결합해 일반 공격과 다른 결과를 만드는가?
5. 시작부터 승리 또는 패배, 재시작이나 로비 복귀까지 이어지는가?
6. 오류 없이 30~60초 실제 플레이 영상을 녹화할 수 있는가?

## 3. P0 — 제출에 필요한 범위

### 게임 흐름

- Relay 참가 코드 기반 온라인 2인
- 호스트가 2명 접속을 확인한 뒤 게임 시작
- 한 개의 게임 맵
- 시간 구간별 웨이브와 최종 보스
- 플레이어 한 명 사망 시 패배
- 보스 처치 시 승리
- 결과 표시와 재시작 또는 로비 복귀

### 전투와 성장

- 이동과 카메라
- 마지막 이동 방향 기반 기본 공격 자동 발동
- 체력, 피해, 사망
- 적 추적, 공격, 생성과 제거
- 경험치 획득과 레벨 증가
- 주몽 기본공격과 P0 스킬 3종
- 레벨업 선택과 실제 강화 적용
- 서로 다른 플레이어 사이의 연계 반응 최소 2개

### 제출 품질

- HP·레벨·EXP, 결과와 최소 조작 안내 UI
- 최소 피격·연계·승패 시각·사운드 피드백
- Windows 제출 후보 빌드
- 심사용 Web 빌드와 공개 링크
- 새 기기 또는 새 Clone 회귀 테스트

기획상 한 판 목표는 15분이다. 개발 중 `StageTest`와 `Main`의 10초·60초 설정은 빠른 흐름 검증값이며 최종 콘텐츠로 보지 않는다.

## 4. P1 — P0 완료 후

- 영웅 2호와 캐릭터 선택
- 추가 연계 반응 2개
- 다운 상태와 동료 부활
- 엘리트 적
- 옵션과 음량 조절
- 연계 발동 통계
- 튜토리얼 안내
- 첫 맵의 비상호작용형 서사 단서와 짧은 캐릭터 소개

## 5. P2 — 해커톤 이후

- 최대 4인 온라인과 매치메이킹·로비 고도화
- 다양한 캐릭터와 스킬 트리
- 20~30분 콘텐츠, 여러 맵과 보스
- 메타 성장과 저장
- Steam 초대·업적·패드·접근성
- AI 동료 또는 AI 디렉터

## 6. 제출 전에는 하지 않을 것

- 3D 전환
- 계정과 자체 서버
- 상점과 과금
- 복잡한 인벤토리
- 스토리 컷신
- 절차적 맵 생성
- 4인 최적화
- 랭킹·경쟁 모드
- 모바일 조작 대응

## 7. 네트워크 범위 결정

- 기술: Netcode for GameObjects + Unity Multiplayer Services/Relay
- 제출 목표: 온라인 2인 유지
- 2026년 8월 2일: 같은 Windows 빌드의 Editor·실행 파일로 Relay 참가, `Main` 동시 전환, 플레이어·적·HUD·웨이브·패배와 양쪽 로비 복귀를 확인해 로컬 2인 폴백으로 전환하지 않기로 함
- 2026년 8월 7일: 기본·폭발·편전·적토마의 서버 피해 권한과 감전·분쇄 연계 2종을 코드·전용 검증기로 확인. 실제 두 화면의 스킬·연계 피드백은 별도 회귀가 필요함
- 2026년 8월 9일: `MainMenu → MultiPlayerEntry → MultiPlayerLobby → Main` 메뉴·입장·캐릭터 선택 흐름에 2인 시작 게이트와 선택 캐릭터의 전투 구성을 연결함. 코드·씬 정합성과 실제 2인 회귀를 확인했으며 추가 캐릭터·장시간 재접속은 별도 검증이 필요함
- 아직 별도 확인할 항목: 새 메뉴 경로의 2인 Relay, 보스 승리와 연속 재시작, 새 흐름으로의 로비 복귀, 강제 이탈, 10분 이상 지속, Web 환경

결정 근거는 `08_DECISION_LOG.md`, 세부 테스트 결과는 `10_TEST_PLAN.md`에 기록한다.
